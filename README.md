# WARFRAME-RELIC · 星际战甲遗物辅助工具

一款基于 **PySide6** 的 Windows 桌面辅助工具，专为《Warframe》（星际战甲）玩家打造。通过屏幕截图 + OCR 文字识别，自动识别画面中的遗物、部件与物品，提供出入库状态、掉落部件、实时价格、世界状态战报等信息，并附带技能 CD 辅助、护眼遮罩、全局快捷键等便利功能。

> 界面风格：**Cyberpunk Chamfered（赛博朋克切角风）**，支持多主题与沉浸黑模式。

---

## 功能特性

### 核心识别
- **遗物状态检查**：框选/全屏截图后自动识别遗物，标注「入库 / 出库」状态（金/银/铜图例对应必掉/常见/稀有）。
- **遗物内含查询**：识别遗物后展示可开出的部件清单。
- **物品翻译**：中英文物品名互译，OCR 识别文本自动纠错匹配。
- **价格查询**：对接 [warframe.market](https://warframe.market) 数据，展示均价 / 最低价 / 中位价；网络不佳时自动降级为本地缓存数据并明确提示，不会白屏卡死。

### 辅助功能
- **世界状态（一线战报）**：展示游戏世界状态信息，启动预热 + 磁盘缓存，离线可看上次数据。
- **技能 CD 辅助**：屏幕悬浮层追踪技能冷却（数字键 `1~4` 触发）。
- **护眼遮罩**：一键在屏幕上覆盖暗色遮罩，保护夜间游戏视力。
- **窗口置顶**：一键把主窗口拉到最前。
- **辅助触发器**：鼠标 / 键盘触发后自动执行按键、点击、鼠标移动等动作链，支持鼠标侧键 1 / 侧键 2（按下 + 抬起）等多种触发方式。
- **🆕 ScrLK 快捷总控**：一键启用后，所有已开启的触发器是否生效完全跟随键盘上的 **ScrLK（Scroll Lock）灯**——灯亮生效、灯灭暂停，游戏里随时一键"静默/开火"，无需切出游戏翻开关，详见下文。

### 快捷键与主题
- **全局快捷键自定义**：所有快捷键可在「功能开关」页点击输入框后直接按下新组合键进行修改。
- **快捷键占用诊断**（新）：自动检测每个快捷键是否被其他程序占用，状态灯一目了然，详见下文。
- **双主题**：赛博朋克（cyberpunk）/ 玻璃拟态（glassmorphism），基于 Token 体系，支持沉浸黑模式与像素字体自定义。

## 默认快捷键

| 快捷键 | 功能 |
|---|---|
| `Ctrl + G` | 区域选择（框选截图） |
| `Ctrl + H` | 全屏捕获（全屏截图识别） |
| `Ctrl + J` | 护眼遮罩 开 / 关 |
| `Ctrl + B` | 窗口置顶（一次性拉到最前） |
| `1` `2` `3` `4` | CD 辅助对应 4 个技能 |

> 以上均可在「功能开关」页自定义。若某组合键按了没反应，大概率是被其他常驻软件（常见：OBS / 录屏软件、输入法、QQ 等）全局占用，请使用下面的诊断功能排查。

## ScrLK 快捷总控（新）⭐

游戏中经常有这种需求：**触发器平时开着，但过场动画、对话菜单、整理装备时又怕鼠标误触连点**。为此新增了一个独立的「ScrLK 快捷总控」开关——用键盘上几乎用不到的 **ScrLK（Scroll Lock / 滚动锁定）键**当作物理总闸，不用切出游戏就能瞬间静音 / 恢复全部触发器。

**使用方法（3 步）：**

1. 在「辅助触发器」页或「功能开关 → 辅助触发器」卡片顶部，打开 **ScrLK 快捷总控**；
2. 保持你需要的触发器为开启状态（比如 1 / 2 / 3 三个）；
3. 游戏中直接按键盘上的 **ScrLK 键** 切灯：
   - 🟢 **灯亮 → 触发器全部生效**；
   - 🔴 **灯灭 → 触发器全部暂停**（状态约 200ms 内切换）。

**设计细节：**

- **两层独立状态**：总控只在引擎执行入口加一道门禁，**不会改动任何单个触发器自己的开关**——灯灭时子开关仍显示 ON，按亮后原样恢复，配置零丢失风险；
- **总控关闭即完全无感**：不开启该功能时，一切行为与旧版完全一致；
- **实时状态可见**：开关右侧实时显示「ScrLK 灯亮 · 生效中 / 灯灭 · 已暂停」，没有指示灯的紧凑型键盘也能确认当前状态；
- **两处入口同步**：触发器配置页和功能开关页都能切换，状态实时双向同步，并在重启后保持；
- 读取的是 ScrLK 的**系统灯态**而不是按键事件，软件启动前灯是亮是灭都能正确识别，且不拦截 ScrLK 键原有的切灯功能。

> 小提示：部分紧凑键盘需要 `Fn + 某键` 才能按到 ScrLK（常见印为 `ScrLk` / `Scroll Lock`），具体组合请参考键盘上的丝印标识。

## 快捷键占用诊断（新）

「按了快捷键完全没反应，却不知道为什么」是本工具最高频的疑难场景——根因通常是**其他程序抢先全局注册了同一个组合键**（Windows 返回错误码 1409）。本功能让该问题可见、可排查：

- **状态灯**：「功能开关」页每个可注册快捷键旁有一个小圆点：
  - 🟢 绿灯：注册正常；
  - 🔴 红灯：已被其他程序占用或与本软件其他快捷键冲突（鼠标悬停可见具体原因）。
- **重新检测**：点击「重新检测」按钮可随时重新探测全部快捷键（例如关掉占用程序后点一下，红灯即可转绿）。
- **红色诊断条**：页面顶部汇总所有异常快捷键的中文功能名，并给出排查建议。
- **改键即时预检**：修改快捷键时实时检测新组合键——若被外部占用或与本软件其他键冲突会立即警告（仍允许强制保存）。
- **启动不打扰**：软件启动时即使发现快捷键被占用也不弹弹窗打断，进入页面后红灯可见。

> 说明：受 Windows 系统限制，目前无法反查「具体是哪个程序」占用了快捷键，只能提示该组合键已被占用。

## 快速开始

### 环境要求

- Windows 10 / 11（使用了 Win32 全局快捷键与 DX 截图，暂不支持其他系统）
- Python 3.10+

### 开发模式运行

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 单次启动（不监听文件变化）
python dev.py --once

# 3. 热重载模式（默认）：修改 .py / .yaml 后自动重启
python dev.py
```

> 开发启动会请求管理员权限（全局快捷键/前台窗口需要），属正常现象。

### 运行测试

```bash
pytest
```

## 打包 EXE 分发

```bash
# 一键打包：PyInstaller 构建 → 自检 → 冒烟启动 → 生成 ZIP
python build.py --zip

# 构建前清理 workpath（遇到诡异打包问题时使用）
python build.py --clean
```

产物输出到 `dist/WARFRAME-RELIC_win64_日期.zip`。

打包要点：
- 入口固定为 `dev.py`（frozen 分支自动跳过提权直接启动）；
- 采用 `--windowed`（不显示黑框控制台）+ `--noupx`（降低杀软误报）；
- 控制台输出在打包环境统一兜底到 `data/logs/console.log`；
- 已排除 torch / pandas / matplotlib 等零引用的重依赖，体积约 494 MB（ZIP 约 176 MB）；
- **打包前请先关闭正在运行的本软件**，避免 EXE / dist 文件被占用导致构建失败。

## 项目结构（分层架构）

```
WARFRAME-RELIC/
├── core/
│   ├── tokens/        # L-Infrastructure：颜色/尺寸 Token 解析（无 Qt 依赖）
│   ├── services/      # L-Service：纯业务逻辑（CRUD / 搜索 / 价格 / 世界状态）
│   ├── recognizers/   # OCR 识别 / 文本纠正 / 物品匹配
│   ├── widgets/       # 自绘赛博风控件（继承 Qt 原生控件 + Mixin）
│   ├── pages/         # L2 页面：组装控件、连接信号
│   ├── state/         # 全局单例状态与事件总线
│   ├── hotkey_manager.py   # 全局快捷键注册 / 占用检测 / 改键预检
│   ├── app_shell.py        # 窗口外壳（新入口）
│   └── paths.py            # 资源/用户数据路径解析（打包安全）
├── data/              # 只读数据资源（预设、词典、文案）+ 用户配置
├── assets/            # 字体、图标
├── docs/              # 设计文档（UI 框架 / 价格架构 / 数据库说明）
├── dev.py             # 开发启动器（热重载 / 打包入口）
└── build.py           # EXE 打包脚本
```

架构铁律：Service 层不依赖 Qt、Widget 层不碰业务数据、所有颜色/尺寸走 Token、资源路径统一走 `core/paths.py`（保证打包后不失效）。
